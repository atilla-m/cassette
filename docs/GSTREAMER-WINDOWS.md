# Windows GStreamer diagnostic strategy for beta.4

Windows 10/11 x86_64 support is being prepared on `feature/windows-beta4`; it is not part of the published Linux beta.3 release. CI builds an **unsigned diagnostic NSIS installer**, not a release asset. Clean Windows desktop qualification and codec-redistribution review remain open.

The CI builder obtains the official GStreamer 1.26.11 MSVC x86_64 runtime and development MSIs from `gstreamer.freedesktop.org`, verifies their pinned SHA-256 values in `scripts/install-gstreamer-windows.ps1`, and uses the development files only while compiling. `scripts/stage-gstreamer-windows.ps1` resolves required playback elements through `gst-inspect-1.0`, rejects non-allowlisted plugin licenses, follows the selected PE DLL dependency closure with MSVC `dumpbin`, and stages only those runtime DLLs, plugin DLLs, the plugin scanner, upstream license texts, and a provenance/hash manifest. The staged directory is ignored and generated only on the Windows runner. Headers, `.lib` files, PDBs, GStreamer test tools, and the development MSI are not bundled.

The Windows-only Tauri configuration places the runtime beside Cassette and includes an offline WebView2 installer. Cassette uses Tauri's default static Visual C++ runtime for its own binary; staging rejects any private GStreamer DLL that still needs an unbundled VC redistributable. Cassette points GStreamer at its private plugin directory and prepends its installation directory to **its own process** environment for the scanner child process; it never edits the user's or system's `PATH`. Missing staged components abort packaging or show a startup error where Windows can load the executable. A missing core DLL may still cause the Windows loader's own error before Cassette starts. The normal repair is to reinstall the verified NSIS package, not to install GStreamer separately.

CI separately runs every selected element from a copied private runtime with the shared GStreamer directory removed from `PATH`. The artifact scanner requires the exact manifest, known element set, core DLL, notices, and matching hashes in the extracted installer; it continues rejecting unlisted GStreamer DLLs and unsafe payloads. This automated check does not establish clean-machine playback or codec patent clearance.

Required playback elements: `playbin`, `uridecodebin`, `decodebin3`, `filesrc`, `typefind`, `audioconvert`, `audioresample`, `autoaudiosink`, `id3demux`, `flacdec`, `oggdemux`, `vorbisdec`, `opusdec`, `wavparse`, `qtdemux`, `avdec_mp3`, and `avdec_aac`. All six supported audio formats still require real desktop playback checks. The Windows application uses the same six-format tag editors on disposable copies; lyrics editing is deferred to beta.5.

The installer is unsigned; Windows may warn before installation. Compare the downloaded artifact's SHA-256 with the recorded CI artifact hash. Windows does not self-install from Cassette's Linux AppImage update feed. A later Windows version must be downloaded from Releases and installed manually; no Windows auto-update or package repository is configured.

Clean Windows 10/11 qualification still needs: no preinstalled GStreamer or manual `PATH`, WebView2 present and absent, per-user install and Start-menu launch, six-format playback, synthetic tag edits, cover-art viewer, persistence after reopening, and uninstall without deleting the test library or profile. Keep the diagnostic library and `%APPDATA%`/`%LOCALAPPDATA%` profile disposable. Check the LGPL and other copied notices against the exact staged DLLs and review codec patent obligations before any Windows publication. GStreamer documents both private runtime deployment and licensing obligations at <https://gstreamer.freedesktop.org/documentation/deploying/windows.html> and <https://gstreamer.freedesktop.org/documentation/deploying/index.html>.
